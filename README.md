# cn-active-fault-earthquake-map · 城市活动断层与历史地震可视化

输入一个中国城市，输出**高德卫星影像 + Leaflet** 的交互式 HTML 地图：
**左右分栏**（左侧信息栏 + 右侧地图区），叠加该城市周边的**活动断层**
（CAFDv2023）、**历史 M≥3 级地震**（可筛选 + 可排序列表，默认只统计**市域内**）
与**城市行政边界**（阿里 DataV.GeoAtlas 三级行政边界）。
断层同样**只展示市域内的**（与边界有交集即保留，越界部分精确裁掉）。

全部数据源免 API Key，零第三方依赖。

---

## 快速开始

```bash
# 最简：默认 200 km 半径、M≥3
python scripts/build_map.py 西安 --out ./xi_an

# 同名城市消歧 + 更大范围 + 只看 M≥4
python scripts/build_map.py 唐山 --province 河北 --radius 300 --min-mag 4.0 --out ./tangshan

# 指定时间范围
python scripts/build_map.py 汶川 --province 四川 --radius 150 --start-year 1950 --out ./wenchuan

# 产出可离线浏览版本（CDN 挂了也能看）
python scripts/build_map.py 西安 --offline --out ./xi_an

# 不画行政边界（跳过边界下载与匹配）
python scripts/build_map.py 西安 --no-boundary --out ./xi_an

# 回退到「半径内全部地震」的旧口径
python scripts/build_map.py 合肥 --province 安徽 --scope radius --out ./hefei_radius

# 索引中查不到的县直接给坐标（如汶川县城威州不在索引中文名里）
python scripts/build_map.py 汶川 --province 四川 --lon 103.59 --lat 31.48 --out ./wenchuan
```

## 统计范围：为什么默认只算市域内

USGS 只支持矩形/圆形查询，脚本用 `--radius` 取数只是**手段**；
页面要回答的是「这个城市发生过什么地震」，所以默认把结果收口到行政边界内。

**合肥实测**：

| 口径 | 事件数 | 最大震级 | 最大震级事件 |
|---|---|---|---|
| 半径 200 km | 20 | **6.4** | 1917-01-24 六安霍山（距合肥 **131 km**） |
| 合肥市域内 | 2 | 4.9 | 2024-09-18 肥东（距合肥 29 km） |

把 131 km 外的霍山 M6.4 说成「合肥的地震」是错的。**退化保护**：只有市域内
**0 条**才退回半径结果，并在概览面板写明原因 —— 宁可多画，不可给一张空图。

**断层也按边界裁剪**：

- **完全在市域内** → 整条保留；
- **与市域有交集**（哪怕只擦到一角）→ **保留**，越界部分按边界折线精确裁掉；
- **完全在市域外** → 不展示。

实现为「折线段 × 边界边」求交切割，并用均匀网格空间索引（`_EdgeGrid`）
把求交量从 42 万次降到约 1 万次。概览面板**单独标注「断层范围」**，
与「统计范围」分开写，避免口径混淆。

## 断层的「活动方式」与「最新活动年代」怎么读

| 原始字段 | 原始值 | 页面显示 | 含义 |
|---|---|---|---|
| 性质 | `正断` | 拉张型（地层被拉长） | 断层两侧被拉开 |
| 性质 | `逆断` | 挤压型（地层被压缩并抬升） | 断层两侧被压短并抬升 |
| 性质 | `走滑` | 水平错动型 | 两侧横向错开 |
| 时代 | `Qh` | 全新世（约 1 万年前至今） | **最后一次活动距今多久** |
| 时代 | `Qp3` | 晚更新世（约 1.3 万–21 万年前） | 同上 |
| 时代 | `Pre-Q` | 前第四纪（260 万年前） | 同上，一般不具活动性 |

**年代越新 = 地壳活动越频繁 = 潜在地震危险性越高。** 同一断层的多个测绘分段
可能记录到不同年代码，表格中取**最新的**那个作为代表。

**「未命名断裂」不是数据缺失。** 断库的断裂名字段填充率约 69%，未命名的段
在清单里统一显示为「未命名断裂」。这类段若带 `zone`（所属断裂带）会在弹窗里
给出归属 —— 例如合肥 9 段中有 6 段无名但都属**郯庐断裂带**（中国东部最重要的
活动构造带，1668 年郯城 8½ 级地震的发震构造）。每条断层还带 `ref`（参考文献），
是可溯源性的依据。

## 坐标系

高德瓦片是 **GCJ-02**，地震与断层数据是 **WGS84**。脚本在写入前对地震点、
断层线、城市中心统一做 WGS84 → GCJ-02 偏移，否则要素整体错位 400–600 m。
偏移算法已用国测局公认校验点验证：

```
(116.404, 39.915)  →  (116.410244, 39.916404)   ✓ 与公认值一致
```

`data.json` 同时保留 `center_wgs84` 与 `center_gcj02`，便于二次分析。

## 离线使用

`--offline` 会在输出目录生成 `leaflet.js` / `leaflet.css`。HTML 优先走 CDN，
CDN 不可达时自动切换到本地副本；两者都不可用时页面中央给出明确提示而非白屏。

> 底图瓦片（高德卫星影像）仍需联网，离线仅保证地图框架与数据要素可用。

## 已知限制

**地震目录完整性存在客观缺口。** USGS/ISC-GEM 合并目录对中国的仪器记录约始于
1960 年代，1970 年后 M≥3 基本完整；此前只有大震级事件被系统编目。
本技能已叠加**国家地震台网 CENC 近期目录**（中文地名、权威），可补近期事件，
但 CENC 仅为实时/近期列表，**历史缺口仍主要来自 USGS**。已验证 USGS 缺口不是查询
参数问题（`includeallorigins=true&includeallmagnitudes=true`
与默认查询事件数相同，160 vs 160），上限来自数据源本身。脚本会在面板顶部给出
完整性提示。正式分析请交叉验证《中国地震年鉴》或中国地震台网正式目录。

其他限制：

- 断层线为地表破裂迹线位置，**不表示破裂深度或分段**
- 高德瓦片为商业服务，仅供浏览参考，不可再分发
- 活动断层库覆盖中国大陆及邻区，边疆地区精度低于东部

## 目录结构

```
cn-active-fault-earthquake-map/
├── SKILL.md
├── README.md
├── _user_meta.json
└── scripts/
    ├── build_map.py        # 主脚本
    ├── template.html       # HTML 模板（版式/样式/JS，外置便于改版）
    ├── boundary_datav.py   # 阿里 DataV 三级行政边界（名称解析 + 边界下载）
    ├── selftest.py         # 205 项自检（无需浏览器，查代码与数据）
    ├── qa_browser.py       # 产物浏览器验收（42 项，需 playwright + 本机 Chrome）
    └── pack.py             # 打包成可上传的技能包（排除中间产物）
```

`selftest.py` 与 `qa_browser.py` 互补、不能互相替代：前者查**数据与代码**
（合并顺序、统计口径、字段完整性、占位符闭合），后者查**渲染结果**
（骨架、概览、目录表、tab、图层开关、点击弹窗、控制台错误）。
跑 `qa_browser.py` 前需起本地 HTTP 服务（`python -m http.server 8899`），
`file://` 会被浏览器拦截。

> **不使用任何磁盘缓存**（v1.0.5 起，应用户要求）：每次运行全部实时取数
> （地震目录 / 断层库 / 行政边界 / 地名索引），下载中的大文件放一次性
> 临时目录、进程退出即删。技能目录内同样零缓存文件（含 `__pycache__`）。
> 数据永远最新，也不再有「旧缓存静默遮蔽新逻辑」这类故障模式；
> 速度由「断库 16 路分块并发下载 + 四路取数并行」保证（见下方性能表）。

## 实现要点速查

供二次开发参考，全部来自真实实测：

**数据与坐标**

- 一律用 GET（本机网关拦 POST 返回 504）
- Windows `time.gmtime` 不支持负时间戳，用 `datetime` + `timedelta`
- `CN-faults.gmt` 是 GMT 段式文本，字段位置：中文名 2 / 英文名 3 / 性质 6 / 时代 8
- GADM `NL_NAME_1` 是「繁体|简体」竖线格式，取竖线后一段再归一化
- 行政区名打分函数不能有恒真条件（`stripped == want` 恒真 → 返回过「安康市」）
- 不剥「市」后缀做地名归一化（`西安` 会与 `西安新城区` 混淆）
- 边界匹配必须用原始输入名 `args.city`，不能用「省·市」拼接展示名
- 换边界数据源必须重新确认坐标系（DataV 本身是 GCJ-02，再转会二次偏移）
- DataV 省级过滤要沿 parent 链上溯（县级的 parent 是地级市）
- GCJ→WGS 逆变换必须每轮从原始 GCJ 重算（累积写法会偏到公里级）

**裁剪与几何**

- 折线裁剪必须按连通性分段，否则会跨多边形间隙硬连出不存在的断层
- 空间索引提速的前提是不改变结果 —— 必须做「网格 vs 逐边扫描」等价性对照
- 射线法判定前可先做逐环 bbox 剪枝（纯剪枝，不改判定结果）
- 边界环要保留内环（洞），否则洞里的点会被判为在边界内
- 地震去重要用 `time+lon+lat+mag` 指纹（只按 id 会让无 id 要素全塌缩成一条）
- 断层名不得用断裂带名回填（会错误合并不同断层）

**前端与 CSS**

- `L.tooltip(options, content)` 第二参数是图层不是文本，传错会中断整个渲染循环
- 地图初始化必须幂等（CDN 与本地回退脚本都可能触发启动）
- tab 面板的 `display` 规则必须带 `.on` 限定（ID 选择器权重压过类选择器）
- CSS 动画值优先于普通声明，权重更高也压不住，必须 `!important` + 暂停动画
- `getComputedStyle` 在 transition 未走完时返回旧值
- flex 容器里不要塞需要独占一行的兄弟节点（直方图轴标签会被挤成几十像素）
- `.sw` 是 `height:0` 横线，`box-shadow` 会把它撑成方块
- 图例与地图是两套渲染，必须同源对齐，否则图例会「说谎」
- 筛选器与目录表联动靠 `data-i`，漏写时表格显隐全错但地图仍正常
- 排序必须作用于全量索引；`for` 后紧跟 `if/else` 一律加花括号（dangling else）

**工程与缓存**

**工程要点**

- 不使用磁盘缓存（应用户要求）：每次运行实时取数，大文件走一次性临时目录、退出即删
- 「旧缓存静默遮蔽新逻辑」这类故障随缓存整体移除而消失（历史教训：belt 字段恒为空）
- 静默的 `except Exception: return []` 会伪装成功，兜底分支必须可观测
- 模板外置后自检断言必须改指向，否则断言永真、静默失效却报告「通过」
- 断言要防「永真」：只查键名 / 只查变量名 / 宽泛子串三种典型形态
- 数据异常先怀疑验证脚手架；测试替身签名必须与生产函数逐参数对齐

## 速度

构建流程每步打印 `⏱` 阶段耗时。v1.0.5 起无磁盘缓存，实测（合肥，
2026-10，本机网关）**冷跑全流程 83 s**，分阶段：

| 阶段 | 耗时 | 手段 |
|---|---|---|
| 地名解析 | 0.27 s | DataV 索引实时下载（340 KB）+ 本地计算 |
| ② 四路取数（并行） | **81.8 s** | 墙钟 = 最慢一路（断库下载）；USGS/CENC/边界被完全覆盖 |
| ├ 断库下载 | ~58–75 s | 16 路分块并发（实测 8 路 92 s → 16 路 58 s；32 路反而不稳） |
| ├ USGS 地震目录 | ~5 s | count 与 query 并发 |
| ├ CENC 近期目录 | ~1 s | 单次 GET |
| └ DataV 行政边界 | ~0.2 s | 单要素下载 |
| ③–⑦ 转换/边界/裁剪/收敛/渲染 | < 0.1 s | 纯本地计算 |

**为什么无缓存还能接受**：四路并行后墙钟由断库下载单独决定；本机网关对
GitHub 系主机的聚合带宽约 140 KB/s（7.9 MB 断库的物理下限 ~58 s），
这是网络限制而非代码限制。若需反复跑同一城市，可自行保留输出目录，
不必依赖技能缓存。
